# Локализация интерфейса (T-074)

Механизм: `src/shared/i18n/index.ts`, постоянные ID — `src/shared/i18n/legacy.json`, реестр языков — `src/shared/i18n/locales.json`, каталоги — `src/shared/i18n/catalogs/*.json`, React-помощники — `src/renderer/src/i18n.tsx`.

## Как устроено

- Вызовы `t()` и `tx()` используют постоянный ID вида `msg.66962f72a0888373`. Английский текст этого ID хранится
  в `catalogs/en.json`, русский — в `catalogs/ru.json`. JSON-ключи сортируются лексикографически.
- `legacy.json` сопоставляет старые английские ключи постоянным ID. Старые вызовы `t('Discard changes')` пока
  поддерживаются; новые вызовы пишутся с ID. Тип `Message` принимает обе формы на время миграции. После правки
  английского текста ID и старый ключ в `legacy.json` **не меняются**, поэтому переводы сохраняются.
- Множественное число: английское `other` содержит `{count}`. В `ru.json` — объект
  `{ one, few, many, other }`, в `en.json` — `{ one, other }` под тем же ID.
- Одинаковый текст с разным смыслом получает разные ID. Исторический префикс контекста, например
  `action|Edit` и обычный `Edit`, сохраняется в `legacy.json`, а переводчик видит текущий английский текст в `en.json`.
- Текст с элементами внутри: `tx('Open {link} to continue', { link: <a …>{t('the settings')}</a> })`
  из `src/renderer/src/i18n.tsx`.
- Текст, известный только во время работы (подписи настроек и команд из схем, названия тем): `translate(text)`.
  Такие строки тоже должны быть в каталогах (это проверяет тест покрытия).
- Даты: `formatDate(ms, options)` из `src/shared/i18n` вместо `new Intl.DateTimeFormat(undefined, …)`.
- Язык: настройка `ui.language` (`system` или код из реестра), переключение без перезапуска: корень `App`
  перерисовывается целиком, `t()` читает текущий язык. Поэтому **нельзя** вычислять переведённые строки
  на уровне модуля (константой при импорте) — только во время отрисовки или вызова.

## Как менять перевод

1. Найдите английский текст среди значений `catalogs/en.json`, скопируйте его ID и измените значение с этим ID
   в нужном каталоге. TypeScript менять не нужно.
2. Для новой строки в коде получите ID командой `npm run i18n:id -- 'English text'`. Добавьте пару
   `"English text": "msg.…"` в `legacy.json`, английский источник в `en.json`, русский перевод в `ru.json`, затем
   вызов `t('msg.…')`. Для формы множественного числа задайте `one` и `other` в `en.json` вручную.
   `npm run i18n:sync` может добавить простой английский источник из новой пары в `legacy.json` и `ru.json` и
   отсортировать каталоги. После создания ID не пересчитывайте его при редактуре текста.
3. Запустите `npm run i18n:check`. Он сообщает о пропущенных и неиспользуемых ключах, дублях,
   ошибках JSON, несовпадающих `{параметрах}` и формах множественного числа. Тексты настроек,
   команд и тем дополнительно проверяет тест покрытия, включённый в эту команду.

Если смысл строки изменился, создайте новый ID; при простой редактуре сохраните прежний. Переводите целое
предложение, сохраняя имена параметров. Имена файлов и ключи JSON не переводятся.

## Как добавить язык

1. Добавьте объект с кодом языка и его самоназванием в `locales.json`. Языки `en` и `ru` обязательны.
2. Добавьте `catalogs/<код>.json`. В нём можно начать с нескольких строк. Непереведённые сообщения и отсутствующие формы множественного числа отображаются по-английски. Для переведённой формы сохраняйте все `{параметры}` английского источника.
3. Запустите `npm run i18n:check`: он покажет покрытие языка и проверит формы множественного числа по `Intl.PluralRules`. Затем проверьте длинные подписи и работу выбора языка в интерфейсе.

Немецкий `de` — частичный проверочный каталог. Письмо справа налево требует отдельной проверки раскладки.

## Что переводить

- Текст в JSX, атрибуты `title`, `aria-label`, `placeholder`, `alt`, подписи пунктов контекстного меню,
  заголовки и тексты диалогов, уведомления и тосты, сообщения об ошибках, которые показывает **наш** код.
- Строки, склеенные из кусков, — превращать в одно предложение с плейсхолдерами (порядок слов в русском другой).

## Что НЕ переводить

- Сообщения git и вывод внешних программ (их разбирает код; git запускается с `LANGUAGE=en_US`).
- Имена классов, id, `data-*`, ключи настроек, аргументы git, имена веток и ссылок, пути, иконки codicon.
- Сообщения в `console.*`, журналы, тексты в тестах.
- Названия продуктов и сервисов: Forklift, Git, GitHub, GitLab, Forgejo, Gitea, GitVerse, Gravatar, Ollama, Kraken (стиль).
- Названия языков в выборе языка («English», «Русский»).

## Проверки

- `npm run i18n:check`: синтаксис и порядок JSON, повторные ключи, полный набор строк из вызовов,
  устаревшие строки, плейсхолдеры и формы множественного числа; также проверка текстов схем.
- `src/shared/i18n/i18n.test.ts`: работа переключения языка, параметров и множественного числа.
- Тест покрытия схем: все подписи настроек, разделов, вариантов и команд есть в словаре.
- Сквозные проверки запускаются с `--lang=en-US` (ищут элементы по английским подписям); отдельный набор
  открывает приложение по-русски и проверяет, что не осталось английских строк и раскладка не ломается.
