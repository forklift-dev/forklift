# Как помочь с переводом Forklift

Переводы интерфейса принимаются через pull request. Можно улучшить существующий язык или начать новый, меняя JSON-файлы без правок кода приложения. [English guide](translating.md).

## Выберите строку

Английский источник — [`src/shared/i18n/catalogs/en.json`](../src/shared/i18n/catalogs/en.json). Найдите текст среди **значений**, скопируйте стоящий рядом ID `msg.…` и найдите его в каталоге нужного языка в `src/shared/i18n/catalogs/`. Меняется только **значение**, ID остаётся прежним:

```json
"msg.19766ed6ccb2f4a3": "Отмена"
```

[Таблица старых ключей](../src/shared/i18n/legacy.json) сохраняет контекст вроде `action|Edit` и обычного `Edit`: для разных смыслов назначены разные ID. Если смысл неясен, укажите в PR ID и экран. При редактуре формулировки ID сохраняется; при изменении смысла нужен новый ID.

## Измените или добавьте язык

Для существующего языка исправьте его каталог, сохраняя алфавитный порядок ключей. Английский и русский каталоги полные; новый язык может быть неполным. Отсутствующие строки показываются по-английски.

Для нового языка добавьте `{ "code": "xx", "name": "Самоназвание" }` в [`locales.json`](../src/shared/i18n/locales.json) и создайте `src/shared/i18n/catalogs/xx.json`. Код может выглядеть как `de` или `pt-BR`. Самоназвание появится в выборе языка. Начать можно с нескольких строк; частичный немецкий каталог служит примером. Приложение подхватит новый каталог автоматически. Для языков с письмом справа налево нужна отдельная проверка раскладки.

Правила перевода:

- Сохраняйте все `{параметры}` с теми же именами и фигурными скобками. Параметр можно переставить внутри фразы.
- Для множественного числа переводите нужные языку формы. `Intl.PluralRules` выбирает `zero`, `one`, `two`, `few`, `many`, `other`; отсутствующая форма показывается по-английски. Список форм можно узнать командой `node -e "console.log(new Intl.PluralRules('xx').resolvedOptions().pluralCategories)"`, подставив код языка. В каждой добавленной форме сохраняйте `{count}`.
- Не переводите названия продуктов, команды Git, пути, имена веток, ключи настроек и код. Вывод самого Git в каталог не входит. Для русского используйте [глоссарий и правила стиля](i18n.md).
- Переводите предложение целиком, с естественным порядком слов.

## Проверьте результат

Можно редактировать JSON прямо на GitHub и дождаться проверки CI в PR. Для локальной проверки подготовьте [среду сборки](../README.ru.md#сборка-из-исходников), затем запустите:

```bash
npm ci
npm run i18n:check
npm run dev
```

`i18n:check` указывает каталог и ID при ошибке JSON, повторном или неизвестном ID, несовпадении `{параметров}` и неверных формах множественного числа. Для дополнительного языка команда показывает покрытие и число записей с неполными plural-формами. `npm run i18n:sync` нужен при добавлении новой английской строки в код, для обычного перевода он не нужен.

В приложении откройте Настройки через шестерёнку или Ctrl+, и выберите **Интерфейс → Язык**. Переключение действует без перезапуска. Проверьте переведённые экраны, диалоги, узкое окно, длинные подписи, подсказки и выбор языка. Для нового языка проверьте также вариант **Система** при соответствующем языке ОС. Скриншот помогает заметить проблемы с раскладкой.

## Отправьте pull request

Создайте ветку или форк, закоммитьте каталог и при необходимости `locales.json`, затем откройте PR в этот репозиторий. Укажите:

- Код языка и тип изменения: новый язык или исправление существующего.
- Какие экраны или группы строк переведены; вопросы по терминологии.
- Результат `npm run i18n:check` или отметку, что проверку выполнит CI; скриншоты для длинного текста.

Сопровождающие проверяют формулировки и контекст, параметры и plural-формы, CI, а также обрезку текста и доступность на затронутых экранах. При необходимости они попросят носителя языка проверить формулировки. Неполный перевод допустим; долю английского текста видно в отчёте проверки. README и другая документация — отдельные Markdown-файлы: изменения в [`README.md`](../README.md), [`README.ru.md`](../README.ru.md) или `docs/` лучше предложить отдельным PR или явно выделенным коммитом. Каталог интерфейса не переводит эти файлы автоматически.

Чеклист ревью:

- [ ] В PR указаны язык, объём перевода и вопросы по терминологии.
- [ ] `i18n:check` прошёл в CI; параметры и формы множественного числа соответствуют источнику.
- [ ] Затронутые экраны, длинные подписи и выбор языка читаются и доступны.
