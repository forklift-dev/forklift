# T-035. Stash

## Цель

Панель stash: создать (с сообщением, с неотслеживаемыми, только staged), применить, pop, удалить, просмотреть содержимое (файлы и diff), stash в графе.

## Контекст

- В GitKraken: Stash 115 строк (по `strings.json`); их реализация — ориентир по поведению, код свой.

## Этапы

- [x] Создать: сообщение, --include-untracked, --staged (git ≥ 2.35 — проверка версии)

## Нюансы

- 2026-10-23: операции адресуют stash по **sha**, а не `stash@{n}`: позиции сдвигаются, когда stash создают или удаляют
  параллельно (в терминале). `drop` находит текущую позицию по sha в `git stash list`.
- 2026-10-23: в графе stash — квадратный узел пунктиром прямо над своим базовым коммитом; внутренние коммиты stash'а
  (индекс, неотслеживаемые файлы) не показываются. Stash, чья база не попала в историю (ветка удалена), в графе не
  виден — только в левой панели. Удаление старого stash'а не меняет `refs/stash`, поэтому версия истории учитывает
  весь список stash'ей.
- 2026-10-23: детали stash'а: изменения относительно базы + файлы третьего родителя (неотслеживаемые) как
  добавленные, с пометкой «untracked»; их diff открывается по коммиту неотслеживаемых файлов (`CommitFile.sourceSha`).
- 2026-10-23: apply — сначала с `--index`, при «Conflicts in index» — без него (staged становятся unstaged, об этом
  уведомление). Pop = apply + drop только после чистого применения; при конфликте stash остаётся. Та же логика
  используется автоматическим stash'ем при переключении веток (T-023) — общий `StashService`.
- 2026-10-23: проверено: юнит-тесты на реальном git и сквозной набор `stash` (10 проверок).
