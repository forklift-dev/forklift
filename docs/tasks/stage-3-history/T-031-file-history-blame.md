# T-031. История файла и blame

## Цель

История изменений одного файла (с учётом переименований) и построчное авторство (blame) во встроенном редакторе.

## Контекст

- В GitKraken: FileHistory 19, Blame 7 строк (по `strings.json`); их реализация — ориентир по поведению, код свой.

## Этапы

- [x] `git log --follow` для файла: список коммитов, diff файла в каждом (с учётом старого имени)
- [x] Blame: `git blame --porcelain`, колонка sha/автор/дата в поле номеров строк Monaco, полоса возраста, подсказка с сообщением
- [x] Переход из строки blame к коммиту в графе; blame на любой ревизии («Blame here» в истории)
- [ ] Точки входа: кнопка в панели изменений и в деталях коммита — есть; палитра команд — с T-052

## Критерии готовности

- История и blame открываются для файла с 10 000 строк за разумное время, без зависания окна
- Юнит/интеграционные тесты, `npm run typecheck`, `lint`, `test`, сквозной набор в `npm run test:e2e` — зелёные

## Нюансы

- 2026-10-23: blame рабочей копии включает незакоммиченные строки («Not committed yet»). Колонка blame — функция
  `lineNumbers` Monaco (подпись только на первой строке каждого блока), клик по ней — коммит в графе (через
  `history:locate`, даже если он далеко).
- 2026-10-23: найдено и исправлено в работе: blame на старом коммите шёл по нынешнему имени файла — после
  переименования git отвечал «no such path». Теперь используется имя файла в том коммите.
- 2026-10-23: история — до 2000 коммитов (`-n`), пути — буквально (`GIT_LITERAL_PATHSPECS`, имена с `*`).
- 2026-10-23: проверено: юнит-тесты (переименование, буквальные пути, blame с незакоммиченными строками, blame на
  ревизии, файл на 10 000 строк < 5 с) и сквозной набор `file-history` (7 проверок).
