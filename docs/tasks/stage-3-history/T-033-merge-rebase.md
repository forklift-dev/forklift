# T-033. Merge и rebase веток

## Цель

Слияние и перебазирование веток: из контекстного меню и перетаскиванием ветки на ветку в графе/левой панели, как в GitKraken. Состояние «идёт merge/rebase» с продолжением и отменой.

## Контекст

- В GitKraken: Merge 172, Rebase 129 строк (по `strings.json`); их реализация — ориентир по поведению, код свой.

- [x] Merge: по умолчанию (ff если можно) / --no-ff / --ff-only / squash по выбору; сообщение merge-коммита
- [x] Rebase текущей ветки на выбранную; продолжить/пропустить/прервать (баннер T-025)
- [x] Drag-and-drop ветки в левой панели: меню «Merge X into Y» / «Rebase Y onto X»

## Нюансы

- 2026-10-23: merge и rebase запускаются с `--autostash`: незакоммиченные изменения откладываются и возвращаются
  (как GitKraken, который делает автоматический stash перед rebase/reset). Без этого git просто отказывает при
  «грязной» копии. Если владелец захочет спрашивать перед этим — легко заменить на подтверждение.
- 2026-10-23: git сливает и перебазирует только **текущую** ветку. Перетаскивание A на B: если B текущая — Merge A
  into B / Rebase B onto A; если A текущая — Rebase A onto B / Merge B into A; иначе предлагается checkout B.
  Перетаскивание на подписи веток в графе — позже (graph — виртуальный список, нужен свой drop-слой).
- 2026-10-23: squash-merge не создаёт MERGE_HEAD: изменения в индексе, сообщение — в SQUASH_MSG, коммит делает
  пользователь формой коммита (сообщение подставлено). Конфликты squash видны в списке изменений без баннера.
- 2026-10-23: имя/ref проверяется `rev-parse --verify` и не может начинаться с `-` (защита от подстановки опций).
- 2026-10-23: проверено: юнит-тесты на реальном git и сквозной набор `merge-rebase` (9 проверок).
