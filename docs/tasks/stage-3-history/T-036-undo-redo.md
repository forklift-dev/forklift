# T-036. Undo/Redo операций

## Цель

Отмена и повтор последних операций (коммит, checkout, создание/удаление ветки, reset, discard, stash), как Undo/Redo в GitKraken.

## Контекст

- В GitKraken: Undo/Redo 20 строк (по `strings.json`); их реализация — ориентир по поведению, код свой.

## Этапы

- [x] Журнал операций с тем, что нужно для отмены (sha, имя ветки, снимок индекса/рабочей копии, копия discard)
- [x] Отмена через reset/восстановление ветки и тега (тот же объект тега); discard — из сохранённой копии (до 50 МБ)
- [x] Кнопки Undo/Redo в тулбаре (подсказка — что именно), Ctrl/Cmd+Z / Shift+Ctrl/Cmd+Z / Ctrl+Y вне полей и редакторов
- [x] Понятные пределы: что нельзя отменить (push), — объяснение

## Критерии готовности

- Каждый тип операции отменяется и повторяется в тестах
- Юнит/интеграционные тесты, `npm run typecheck`, `lint`, `test`, сквозной набор в `npm run test:e2e` — зелёные

## Нюансы

- 2026-10-23: отменяются: коммит и amend (`reset --soft`, изменения остаются в индексе), checkout (назад, с
  автоматическим stash; ветка, созданная checkout'ом удалённой, удаляется), создание/переименование/удаление ветки,
  создание/удаление тега (`update-ref` на тот же объект — аннотированный тег возвращается как был), reset всех трёх
  видов (mixed — снимок индекса `write-tree`/`read-tree`; hard — `stash create` до reset и `stash apply --index` при
  отмене), discard (копия файлов во временной папке, до 50 МБ; больше — история обрывается), stash push (отмена = pop,
  повтора нет), удаление stash (`stash store`), завершённые cherry-pick/revert/merge/rebase/pull/интерактивный rebase
  (`reset --keep` — незакоммиченные изменения сохраняются или отмена отказывает).
- 2026-10-23: каждая запись проверяет, что репозиторий в том состоянии, в каком действие его оставило (HEAD, ветка,
  нужные ссылки). Если что-то изменили снаружи (терминал, другой клиент) — отмена отказывает с объяснением и журнал
  очищается: лучше не отменить, чем отменить не то. Операция, остановившаяся на конфликтах, тоже обрывает журнал.
- 2026-10-23: журнал — в памяти на сессию (до 50 записей на репозиторий), после перезапуска пуст. Индексация
  (stage/unstage) в журнал не входит: она обратима кнопками.
- 2026-10-23: push отменить нельзя (изменение на сервере) — это сказано в подсказке кнопки Push.
- 2026-10-23: проверено: юнит-тесты на реальном git для каждого типа и сквозной набор `undo` (11 проверок).
