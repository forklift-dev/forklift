# T-030. Поиск и фильтрация в истории

## Цель

Поиск коммитов по сообщению, автору, sha, файлу; фильтрация графа по веткам (показать только/скрыть), переход к HEAD и к выбранной ветке.

## Контекст

- В GitKraken: Graph/history: 305 строк интерфейса (поиск, фильтры, колонки) (по `strings.json`); их реализация — ориентир по поведению, код свой.

## Этапы

- [x] Поиск в main через `git log` (--grep, --author, -S по содержимому, -- путь) и по sha в кэше; результаты с подсветкой в графе
- [x] Строка поиска (Ctrl/Cmd+F), навигация по результатам Enter/↑/↓, Esc закрывает
- [x] Фильтр веток: «только эта ветка» (solo), скрыть ветку, показать все; сохранение по репозиторию
- [x] Переход к HEAD, к ветке/тегу из левой панели (даже если коммит далеко в истории)

## Критерии готовности

- Поиск по 100 000 коммитов не блокирует окно; результаты появляются порциями
- Юнит/интеграционные тесты, `npm run typecheck`, `lint`, `test`, сквозной набор в `npm run test:e2e` — зелёные

## Нюансы

- 2026-10-23: поиск возвращает **индексы строк** той же истории (та же версия и тот же фильтр), а не отдельный
  список — граф подсвечивает совпадения и приглушает остальные, переход к результату прокручивает и выбирает строку,
  подгружая нужную страницу. `git log` получает ровно те же ревизии, что обходит граф (`--stdin`), поэтому результаты
  не расходятся со списком. Поиск — асинхронно в процессе git, окно не блокируется; до 2000 результатов.
- 2026-10-23: «скрыть ветку» исключает её из обхода, а не прячет её предков: общая с другими ветками история остаётся.
  Solo показывает только выбранную ссылку (stash'и при этом не показываются).
- 2026-10-23: фильтр — настройка вида окна, хранится по репозиторию в localStorage окна.
- 2026-10-23: исправлено: переход к строке далеко внизу упирался в ещё неизвестную высоту списка; теперь
  раскрытие само запрашивает страницу со строкой и прокручивает повторно.
- 2026-10-23: проверено: юнит-тесты (поиск по 5 полям, solo/hide, locate) и сквозной набор `search` на 3000 коммитах.
