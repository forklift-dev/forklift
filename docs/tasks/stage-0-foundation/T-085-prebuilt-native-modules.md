# T-085. Готовые сборки nodegit и других нативных модулей для CI

## Цель

Идея владельца (2026-10-26): собирать nodegit под каждую платформу один раз, хранить бинарники в отдельном
репозитории и забирать их при сборке приложения — сейчас большая часть времени workflow уходит на компиляцию
nodegit.

## Контекст

- `.github/workflows/build.yml`: между запусками кэшируется только OpenSSL (`actions/cache`), а nodegit,
  node-pty, nsfw и find-git-repositories компилирует `scripts/rebuild-native.mjs` в каждом запуске на каждой из
  трёх платформ (linux-x64, windows-x64, macos-arm64).
- Результат сборки зависит от: ОС и архитектуры, версии Electron (ABI), версий модулей (lock-файл), патчей
  `rebuild-native.mjs` (v8::External, статический OpenSSL), версии OpenSSL.
- `.gitverse/workflows` (облако только ubuntu x64, 30 мин) — тоже выиграет от готового linux-бинарника.

## Варианты

- **a) Кэш собранных модулей в том же репозитории** (`actions/cache`, ключ — ОС, архитектура, версия Electron,
  хэш lock-файла и `rebuild-native.mjs`). Без нового репозитория; первая сборка после обновления Electron или
  модулей — полная, остальные — минуты. Кэш GitHub живёт 7 дней без обращений и не виден GitVerse.
- **b) Отдельный репозиторий `forklift-native`** (предложение владельца): его workflow собирает модули для
  каждой платформы и публикует архивы в релиз с тегом по ключу выше и файлом SHA-256; `rebuild-native.mjs`
  скачивает архив своей платформы, сверяет хэш, распаковывает, а при отсутствии архива собирает сам. Работает и
  для GitVerse, и для локальной установки разработчика; нужен второй репозиторий и выпуск сборок при каждом
  обновлении Electron/nodegit.
- Рекомендация: начать с **a** (быстро, без новых сущностей), **b** — если кэша не хватит (GitVerse, частые
  холодные запуски) или нужны готовые сборки локально. В обоих случаях бинарники проверяются по хэшу и
  смоук-тестом `require` под Electron, как сейчас в `build.yml`.

## Этапы

- [ ] Решение владельца: вариант a, b или оба; для b — где репозиторий (GitHub/GitVerse), публичный или нет
- [ ] Ключ сборки (ОС, arch, Electron ABI, хэш lock-файла и скрипта, OpenSSL) в одном месте
- [ ] Получение готовых модулей с проверкой SHA-256 и откатом на сборку из исходников
- [ ] Замер времени workflow до и после

## Критерии готовности

- Повторная сборка без изменений Electron/модулей не компилирует nodegit; время workflow сокращено и замерено
- Неверный или подменённый архив не попадает в приложение (хэш), сборка из исходников остаётся рабочей
