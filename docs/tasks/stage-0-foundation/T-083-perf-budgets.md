# T-083. Замеры производительности в CI

## Цель

Предложение (2026-10-26): автоматический набор замеров на больших синтетических репозиториях (история 1 млн+ коммитов, рабочее дерево 200 тыс. файлов) с порогами — чтобы скорость не деградировала незаметно. У GitComet — `crates/gitcomet-perf` и `.github/workflows/perf.yml`.

## Контекст

- Скрипты замеров — `docs/research/bench/` (DevTools: первые строки, скачки, память; status; diff).
- Генератор истории — `scripts/make-history-repo.mjs`.

## Этапы

- [ ] Набор `npm run bench` на сгенерированных репозиториях (без сети)
- [ ] Пороги (бюджеты) и отчёт; в CI — ручной запуск и по расписанию
- [ ] Сравнение с прошлым прогоном

## Критерии готовности

- Регрессия скорости или памяти больше порога видна в отчёте
- Юнит/интеграционные тесты, `npm run typecheck`, `lint`, `test`, сквозной набор в `npm run test:e2e` — зелёные
