# T-067. Техдолг: markdown в описаниях и комментариях PR и issues

## Цель

Решение владельца (2026-10-23): записать техдолгом и сделать позже. Описания и комментарии pull requests и
issues (T-065, потом GitVerse, GitHub, GitLab) пишут в markdown, а приложение показывает их простым текстом:
`**жирный**`, списки, код и ссылки видны как разметка. Нужна безопасная отрисовка markdown, близкая к тому, как
это выглядит на сервере.

## Контекст

- Сейчас текст выводится как есть (`src/renderer/src/components/HostingView.tsx`, `.hosting-text` с
  `white-space: pre-wrap`); `#123` уже превращается в ссылку внутри приложения (`IssueRefs`).
- Текст приходит с сервера и пишется чужими людьми — это недоверенные данные. Владелец за безопасность (решение
  2026-10-23 по T-065: сертификаты и внешние ссылки остаются как есть).
- Окно открывает внешние ссылки только по https (`setWindowOpenHandler` в `src/main/window.ts`), CSP окна не
  пускает внешние картинки и скрипты — это не ослаблять.
- Тот же вывод пригодится для README/описаний в других местах (не обязательно в этой задаче).

## Этапы

- [x] Отрисовка markdown (CommonMark + таблицы, списки задач, зачёркивание из GFM) в React-элементы, **без**
      сырого HTML и без `dangerouslySetInnerHTML` (например, react-markdown без rehype-raw; выбор библиотеки и её
      размер — в «Нюансы»)
- [x] Ссылки: https — во внешнем браузере через существующий обработчик; `#123`, `!123`, упоминания `@user` и
      sha коммитов — внутри приложения, как сейчас `IssueRefs`; прочие схемы (`javascript:`, `file:` и т. п.) — текстом
- [x] Блоки кода с подсветкой (Monaco уже есть — его токенайзер, без нового движка), инлайн-код
- [x] Картинки: не загружать с внешних адресов (CSP и утечка IP/трекинг); показать ссылкой «картинка: имя» —
      или решить с владельцем в «Нюансах»
- [x] Стили — токены темы, контраст во всех темах
- [x] Тесты: юнит на опасные вводы (HTML, `javascript:`-ссылки, огромный текст), сквозная проверка отрисовки в
      виде PR/issue

## Критерии готовности

- Описания и комментарии выглядят как на сервере (кроме картинок), никакой HTML из текста не исполняется и не
  вставляется, CSP и обработчик ссылок не ослаблены
- Юнит/интеграционные тесты, `npm run typecheck`, `lint`, `test`, сквозной набор в `npm run test:e2e` — зелёные

## Нюансы

- 2026-10-23: библиотеки — `react-markdown` 10.1 и `remark-gfm` 4.0 (devDependencies, как React: renderer
  собирается Vite; +102 пакета экосистемы unified в node_modules, в сборку попадает только используемое). Они строят
  React-элементы из синтаксического дерева: `skipHtml` (сырой HTML отбрасывается; по CommonMark строка, начатая
  тегом вроде `<script>`, — HTML-блок целиком), без rehype-raw и без `dangerouslySetInnerHTML`.
- 2026-10-23: `src/renderer/src/components/Markdown.tsx` + `src/renderer/src/markdownRefs.ts`:
  - ссылки: остаются только `https:`, `http:`, `mailto:` (остальное — `javascript:`, `file:`, `data:`, относительные —
    становится пустой ссылкой); внешние открываются через `target="_blank"` → обработчик окна (только https, как
    решил владелец);
  - `#N` → issue/PR в приложении, `!N` → merge request (только GitLab), sha коммита (7–40 hex, с буквой и цифрой) →
    показать в графе, `@user` — выделено, без перехода; внутри ссылок и кода не трогаются;
  - картинки не загружаются: `[image: alt]`, у https — ссылкой на картинку;
  - код: блоки с языком подсвечивает Monaco (`monaco.editor.colorize`); его HTML разбирается DOMParser и
    пересобирается в React по белому списку (только `span.mtkN` и переводы строк), `&nbsp;` → пробелы;
  - текст длиннее 200 000 символов показывается как есть; стили — токены темы.
- 2026-10-23: проверено: юнит-тесты (`markdownRefs.test.ts`: разметка, ссылки на #/!/sha/@, ложные срабатывания —
  `C#`, `a#1`, числа, слова из hex, e-mail, код, HTML и опасные ссылки, 2000 строк); сквозной набор `forgejo` —
  описание PR жирным, блок кода с подсветкой, таблица, внешняя ссылка, картинка не загружена, `<script>` и
  `javascript:` не сработали; `gitlab` — `!1` и `#3` в описаниях.
