# T-066. GitVerse: вход, репозитории, pull requests, issues

## Цель

Второй провайдер (приоритет владельца 2026-10-23): GitVerse на общем слое интеграций из T-065 — вход,
репозитории для clone, pull requests и issues текущего репозитория.

## Контекст

- Владелец хостит проект на GitVerse (там же CI, T-003).
- Перед началом выяснить по документации GitVerse: публичный API (адрес, версия, покрытие PR/issues),
  способы входа (персональный токен, OAuth), лимиты; насколько он совместим с Gitea/Forgejo API — если
  совместим, провайдер может переиспользовать клиент T-065.

## Этапы

- [ ] Разведка API GitVerse, запись результатов в «Нюансы»
- [ ] Провайдер GitVerse в общем слое (учётная запись, токен в safeStorage)
- [ ] Clone из списка репозиториев, панель PR, issues — как в T-065
- [ ] Тесты на имитации API; ручная проверка на аккаунте владельца

## Критерии готовности

- Сценарии проходят на аккаунте владельца
- Юнит/интеграционные тесты, `npm run typecheck`, `lint`, `test`, сквозной набор в `npm run test:e2e` — зелёные
