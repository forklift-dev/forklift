## Нюансы

- draft до согласования; не начинать без владельца.
- 2026-10-23: приоритет владельца — после Forgejo (T-065) и GitVerse (T-066); строится на общем слое интеграций T-065.
- 2026-10-23: владелец: «делаем» — начато после T-060.
- 2026-10-23: вход — персональный токен (User settings → Access tokens): scope `api` (или `read_api` +
  `read_repository`, чтобы только смотреть); адрес `https://gitlab.com` подставляется, self-managed — свой адрес.
  Вход через браузер (OAuth) — как для GitHub, позже (нужна регистрация приложения, см. T-068).
- 2026-10-23: GitLab устроен иначе, чем Gitea/GitHub, поэтому свой клиент (`src/main/hosting/gitlab.ts`) на общем
  слое: транспорт (заголовки, ошибки, таймауты, перенаправления без токена) вынесен в `src/main/hosting/api.ts`,
  контракт — `HostingApi`, выбор клиента — `createClient`. Особенности GitLab:
  - API v4 на `<сервер>/api/v4`, `Authorization: Bearer`; проект — по закодированному пути (`team%2Ftools%2Fcli`),
    поддержаны вложенные группы (remote `group/sub/project`: owner — весь путь группы); список — проекты, где
    пользователь участник, по последней активности;
  - merge requests и issues нумеруются раздельно (`!1` и `#1`): комментарий знает, к чему он (`hosting:comment`
    получил `kind`), в тексте и сообщениях коммитов `!N` открывает MR, `#N` — issue; в панели и форме — «Merge
    requests», номера MR — `!N`;
  - «closed» у GitLab без слитых — для единообразия «закрытые» включают слитые; draft — `draft`/`work_in_progress`;
    конфликты — `has_conflicts`; файлы MR — `/diffs` (GitLab 15.7+), иначе старый `/changes`, строки считаются по
    diff; служебные заметки («changed the description») не показываются;
  - MR из форка: путь и clone URL форка — отдельным запросом проекта; checkout — `refs/merge-requests/N/head`;
  - ошибки: `{"message": "..."}`, `{"message": {"поле": ["..."]}}` или `{"error": ...}` — все разбираются.
- 2026-10-23: проверено: юнит-тесты клиента на имитации GitLab (`tests/e2e/gitlabMock.mjs`), сквозной набор `gitlab`
  (общий сценарий из `hostingProvider.mjs` + «Merge requests», `!1`, комментарий в MR, push с токеном, создание
  MR); запрос к настоящему `gitlab.com/api/v4/user` без токена — 401 `{"message":"401 Unauthorized"}`, как ждёт
  клиент. **Осталось:** проверка на аккаунте владельца (нужен токен GitLab, по желанию).
- 2026-10-23: в тестах push шёл через git с глобальными настройками пользователя (его credential helper мог ждать
  ввода) — push теперь делает само приложение с токеном учётной записи.
