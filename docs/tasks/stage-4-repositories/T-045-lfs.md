# T-045. Git LFS

## Цель

Поддержка Git LFS: определение, track/untrack шаблонов, pull/fetch объектов, отображение LFS-файлов, предупреждение при отсутствии git-lfs.

## Контекст

- В GitKraken: LFS 46 строк (по `strings.json`); их реализация — ориентир по поведению, код свой.

## Этапы

- [x] Проверка `git lfs version`
- [x] track/untrack через UI (.gitattributes)
- [x] LFS-файлы в diff: указатель vs содержимое
- [x] Тесты (пропуск, если git-lfs не установлен)

## Критерии готовности

- LFS-репозиторий клонируется и работает; без git-lfs — понятное предупреждение
- Юнит/интеграционные тесты, `npm run typecheck`, `lint`, `test`, сквозной набор в `npm run test:e2e` — зелёные

## Нюансы

- 2026-10-23: **на машине разработки git-lfs не установлен** (ставить системные пакеты ночью не стал). Проверено
  всё, что от него не зависит; track с установленным git-lfs проверяется в сквозном наборе только там, где он есть,
  а `git lfs pull/fetch` и клон LFS-репозитория со скачиванием объектов не проверены вживую — проверить вручную
  после `apt install git-lfs && git lfs install` (или в CI, T-003).
- 2026-10-23: `git lfs version` проверяется при чтении репозитория (кеш 30 с, так что установка git-lfs
  замечается без перезапуска). Если в `.gitattributes` есть `filter=lfs`, а git-lfs нет — предупреждение над
  графом: LFS-файлы видны как указатели, а новые попали бы в коммит обычными файлами.
- 2026-10-23: LFS-файлы помечены «LFS» в панели изменений (`git check-attr filter`, работает и без git-lfs).
  В diff указатель заменяется содержимым объекта из `.git/lfs/objects/…` (читается напрямую, git-lfs не нужен;
  для worktree — из общего git-каталога); если объекта нет — показан указатель с пометкой «not downloaded».
  Построчный staging LFS-файлов отключён (только целиком), как и для других файлов с фильтрами.
- 2026-10-23: track/untrack — палитра «LFS: Track or untrack files…»: шаблоны из `.gitattributes`, Track
  дописывает ту же строку, что `git lfs track` (`<шаблон> filter=lfs diff=lfs merge=lfs -text`, пробелы как
  `[[:space:]]`), Untrack убирает её; изменение `.gitattributes` остаётся для коммита. Без git-lfs Track
  недоступен (иначе файлы ушли бы в git целиком). «LFS: Pull/Fetch LFS objects» — `git lfs pull|fetch` с
  прогрессом и askpass.
- 2026-10-23: однажды в полном прогоне упал `merge-rebase` («no-ff merge creates a merge commit»: коммит есть, но
  граф не показал его за 15 с); отдельно 4 прогона подряд и повторный полный — зелёные. Похоже на медленный
  прогон под нагрузкой; если повторится — разбираться в T-003 (CI).
- 2026-10-23: проверено: юнит-тесты (`lfs.test.ts`: указатели, шаблоны, check-attr, отказ без git-lfs, правка
  `.gitattributes`, diff со скачанным и нескачанным объектом) и сквозной набор `lfs` (7 проверок без git-lfs).
