# T-047. Хуки

## Цель

Работа с хуками: индикация выполнения хука, вывод хука, коммит без хуков (--no-verify) по явному выбору, поддержка core.hooksPath.

## Контекст

- В GitKraken: Hooks 45 строк (по `strings.json`); их реализация — ориентир по поведению, код свой.

## Этапы

- [x] Индикатор «выполняется хук» при коммите/push
- [x] Опция «Skip hooks» в форме коммита (с предупреждением)
- [x] Учет core.hooksPath
- [x] Тесты

## Критерии готовности

- Хуки видимы и управляемы из UI
- Юнит/интеграционные тесты, `npm run typecheck`, `lint`, `test`, сквозной набор в `npm run test:e2e` — зелёные

## Нюансы

- 2026-10-23: хуки и раньше запускались (коммит и push — через git CLI); теперь они видны. Список хуков —
  `git rev-parse --git-path hooks` (учитывает `core.hooksPath`), исполняемые файлы с именами клиентских хуков
  (на Windows — любые, бита x там нет).
- 2026-10-23: пока идёт коммит и в репозитории есть pre-commit/prepare-commit-msg/commit-msg/post-commit, под
  формой коммита — «Running pre-commit hook…» и последние строки вывода (живьём, из stdout/stderr git commit);
  при push с pre-push — то же в тосте прогресса. Ошибка хука, как и раньше, показывает его вывод (и Details в
  журнале).
- 2026-10-23: «Skip hooks» в форме коммита — только если есть pre-commit или commit-msg; `--no-verify`, подсказка
  говорит, какие хуки и из какой папки не проверят коммит; выбор сбрасывается после коммита (не залипает).
  Для push пропуск хуков не добавлен (в задаче — только форма коммита).
- 2026-10-23: проверено: юнит-тесты (`hooks.test.ts`: список, core.hooksPath, вывод и падение хука,
  --no-verify) и сквозной набор `hooks` (8 проверок). Тост pre-push сквозным набором не проверен.
