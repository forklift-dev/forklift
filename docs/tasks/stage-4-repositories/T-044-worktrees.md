# T-044. Worktrees

## Цель

Рабочие деревья: список, создание для ветки, открытие во вкладке, удаление, prune.

## Контекст

- В GitKraken: Worktree 70 строк (по `strings.json`); их реализация — ориентир по поведению, код свой.

## Этапы

- [x] `git worktree list --porcelain`
- [x] add/remove/prune; открыть во вкладке
- [x] Отображение в левой панели
- [x] Тесты

## Критерии готовности

- Сценарии worktree проходят тестами и через UI
- Юнит/интеграционные тесты, `npm run typecheck`, `lint`, `test`, сквозной набор в `npm run test:e2e` — зелёные

## Нюансы

- 2026-10-23: раздел WORKTREES в левой панели (`git worktree list --porcelain`): ветка или папка, пометки
  «this tab», «main», «locked», «missing». Двойной щелчок / «Open in a new tab» открывает дерево во вкладке
  (обычный репозиторий для приложения: свой статус, граф общий).
- 2026-10-23: создание — «+» или «Check out in a new working tree…» в меню ветки: существующая ветка или новая
  от HEAD (`worktree add [-b]`), папка по умолчанию — рядом с репозиторием `<имя>-<ветка>`; новое дерево сразу
  открывается во вкладке. Ветку, занятую в другом дереве, git отклоняет — сообщение показывается как есть.
- 2026-10-23: Remove (`worktree remove --force`, подтверждение: изменения в нём теряются; ветка и коммиты
  остаются), его вкладка закрывается; главное дерево и дерево текущей вкладки удалить нельзя, запертое — тоже
  (сначала Unlock). Lock/Unlock, Prune missing (`worktree prune`).
- 2026-10-23: проверено: юнит-тесты (`worktrees.test.ts`: разбор porcelain, add для ветки и новой ветки, отказы,
  lock/remove/prune) и сквозной набор `worktrees` (10 проверок).
