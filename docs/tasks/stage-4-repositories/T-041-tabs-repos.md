# T-041. Вкладки репозиториев, восстановление сессии, недавние и поиск репозиториев

## Цель

Несколько открытых репозиториев во вкладках, как в GitKraken. **При запуске открываются те же
вкладки, что были при закрытии** (сейчас приложение всегда стартует без репозитория — замечание
владельца 2026-10-23). Экран управления репозиториями: недавние, избранные, поиск на диске.

## Контекст

- В GitKraken: вкладки (65 строк интерфейса), Repository Management, `find-git-repositories` (уже подключён у нас).
- Сейчас в main один срез `repo`; репликация копирует его в окно целиком.

## Этапы

- [x] Состояние: в main `repos: { view: { tabs, activeId }, byId: Record<id, RepoState> }`, id вкладки = корень
      репозитория; операции (`repo:*`, `index:*`, `commit:*`, `diff:*`, `file:*`, `tools:*`, `git:*`) получают id явно
- [x] Репликация: в окно — `tabs` (метаданные всех вкладок) и `repo` (полные данные только активной) через проекцию
      `projectState`; истории неактивных вкладок не копируются
- [x] Вкладки: открыть (после активной; уже открытый — переключиться), закрыть (× / средняя кнопка / Ctrl+W),
      переупорядочить перетаскиванием, Ctrl+Tab / Ctrl+Shift+Tab, Ctrl+1…8, Ctrl+9 — последняя; «+» и Ctrl+T —
      экран Repositories
- [x] **Восстановление сессии**: вкладки и активная сохраняются в `userData/repositories.json` при каждом изменении;
      при запуске открываются (настройка General → «Reopen repositories at startup», по умолчанию вкл.); читается
      только активная, остальные — при первом показе; недоступный путь — вкладка с объяснением, «Try again» и «Remove tab»
- [x] Экран «Repositories»: недавние (с датой открытия), избранные (звёздочка), поиск git-репозиториев в выбранной
      папке (`find-git-repositories`, в фоне, с остановкой), открытие по пути и перетаскиванием папки в окно
- [x] Аргументы командной строки: `forklift <путь>` открывает репозиторий во вкладке (и во уже запущенном экземпляре
      через `second-instance`); ошибка — уведомление над содержимым окна
- [x] Тесты: модель вкладок, проекция состояния, сохранение/восстановление, несуществующие пути, argv, поиск;
      сквозной набор `tabs` (26 проверок)

## Критерии готовности

- Перезапуск приложения возвращает вкладки и активный репозиторий; переключение мгновенное
- Юнит/интеграционные тесты, `npm run typecheck`, `lint`, `test`, сквозной набор в `npm run test:e2e` — зелёные

## Нюансы

- Задача меняет структуру состояния и IPC — делать **до** большинства функций этапов 2–3, чтобы не переделывать их.
- Вкладки разных репозиториев не должны мешать друг другу: очередь операций индекса (T-021) — по репозиторию.
- 2026-10-23: **новые функции этапов 2–3 следуют этой схеме**: команда принимает `repo` (id вкладки) первым
  аргументом, main проверяет, что вкладка открыта (`tab(repo)` в handlers.ts), после изменения — `loadRepo(id)`.
  Окно берёт id из `data.root` активного репозитория.
- 2026-10-23: проекция `projectState` возвращает только существующие объекты состояния main — репликация
  сравнивает срезы по ссылке, поэтому обновление неактивной вкладки не посылает в окно её данные (тест в
  `reposSlice.test.ts`). Метаданные вкладок (`loading`, `error`) меняются при каждом чтении — это маленький срез.
- 2026-10-23: восстановленный путь, который теперь резолвится в **другой** репозиторий (папку удалили, а родитель —
  тоже репозиторий), не подменяется: «No repository at … any more».
- 2026-10-23: файл сессии пишется только при изменении набора/порядка вкладок, активной или библиотеки (не при каждом
  `loading`), атомарно (`AtomicFile`, общий с settings.json). Повреждённый файл → `repositories.json.damaged`, старт без
  восстановления.
- 2026-10-23: `find-git-repositories` не заходит внутрь найденного репозитория (вложенные не находит) и не сообщает
  связанные worktree (`.git`-файл) — это поведение модуля; worktree появятся в T-044. Возвращает пути к `.git`,
  мы приводим к корню. Глубина поиска — 6 уровней, не больше 2000 результатов.
- 2026-10-23: аргументы второго экземпляра: Chromium переставляет ключи (`--…`) перед позиционными аргументами, поэтому
  путь ищется среди позиционных, а в dev первый позиционный — путь приложения (`electron .`). Баг найден сквозным
  набором (второй запуск открывал папку проекта), покрыт юнит-тестом.
- 2026-10-23: меню приложения: на Windows/Linux меню убрано (`Menu.setApplicationMenu(null)`) — иначе стандартное
  меню Electron перехватывает Ctrl+W (закрыть окно) и Ctrl+R (перезагрузить окно). На macOS — минимальное меню
  (приложение, Edit, Window) без Cmd+W. В dev DevTools — F12 / Ctrl+Shift+I. Полная раскладка сочетаний — T-052.
- 2026-10-23: перетаскивание папки в окно: `File.path` в Electron больше нет, путь даёт `webUtils.getPathForFile`
  в preload (`window.forklift.pathForFile`). Сквозной тест не покрывает (CDP не умеет бросать настоящие файлы) —
  **проверить вручную**: перетащить папку репозитория из файлового менеджера в окно.
- 2026-10-23: на macOS `open-file` (перетаскивание на иконку в Dock) не обрабатывается — добавить вместе с T-003/T-004.
- 2026-10-23: проверено в dev и в упакованной сборке (`E2E_BINARY`): все наборы зелёные.
