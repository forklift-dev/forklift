# T-103. Диагностика здоровья репозитория

## Цель

Экспериментальная диагностика: целостность Git-объектов, размер loose/packed объектов, крупные файлы и доступные рекомендации. Диагностика по умолчанию только читает; очистка или обслуживание требуют отдельного подтверждения.

## Контекст

По решению владельца от 2026-10-28 функция экспериментальная: вся её UI-точка входа и связанные controls должны быть скрыты при выключенной настройке `general.experimentalFeatures`. Общий переключатель описан в [T-100](../stage-5-settings/T-100-experimental-features.md).

## Этапы

- [x] Добавить read-only отчёт `fsck`, размера object store и больших tracked-файлов (10 МБ и больше, до 10 000 достижимых объектов).
- [x] Добавить unit и e2e проверки, включая выключенный флаг.
- [x] Прогнать typecheck, lint, i18n:check, unit и e2e сценарий branches.

## Критерии готовности

- Экспериментальная диагностика: целостность Git-объектов, размер loose/packed объектов, крупные файлы и доступные рекомендации. Диагностика по умолчанию только читает; очистка или обслуживание требуют отдельного подтверждения.
- При выключенных экспериментальных функциях никакая точка входа этой функции не отображается.
- При включении функция доступна, состояние корректно переживает перезапуск и соответствует настройке.
- Тесты и документация задачи обновлены.

## Нюансы

- 2026-10-28: владелец попросил сделать все четыре функции доступными только через явный opt-in в настройках.
- 2026-10-28: диагностика ничего не исправляет и не обслуживает автоматически. Object store показывает размер, loose/packed objects и число pack-файлов; предупреждения `dangling`/`unreachable` выводятся как сведения, а ошибки fsck требуют внимания. Проверки выше проходят.
