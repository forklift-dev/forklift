# T-021. Индексация (файлы, фрагменты, строки) и коммит

## Цель

Stage/unstage/discard файлов, отдельных фрагментов (hunk) и выделенных строк прямо из встроенного diff;
поле сообщения и коммит с запуском хуков.

## Контекст

- GitKraken: Hunk View со Stage/Unstage/Discard Hunk и «Stage selected lines»; hunk'и — jsdiff
  `structuredPatch` по полным текстам; индексация фрагмента — применение патча к версии из индекса и
  запись нового blob'а в индекс (см. T-020).
- libgit2 не запускает хуки (`pre-commit`, `commit-msg`) — коммит через git CLI (T-012).

## Этапы

- [x] Файлы: `index:stage`, `index:unstage`, `index:discard` через git CLI (`add -A`, `restore --staged` / `rm --cached` без HEAD, `restore --worktree`, удаление неотслеживаемых), кнопки у файла и группы
- [ ] Hunk View: отдельный режим «только фрагменты» — пока его роль выполняет «Collapse unchanged» Monaco
- [x] Фрагменты и строки: новый текст из line changes Monaco (`src/main/git/partial.ts`), запись `hash-object --path` + `update-index --cacheinfo`; иконка у hunk'а, контекстное меню, кнопки «… lines»
- [x] Discard фрагмента/строк в рабочей копии — с подтверждением (свой диалог, фокус на Cancel)
- [x] Коммит: заголовок/описание, `git commit --file=-` (хуки, подпись по настройкам git), Amend с подстановкой сообщения, Ctrl/Cmd+Enter

## Нюансы

- Конец файла без `\n`, CRLF, `core.autocrlf` и фильтры (LFS, `.gitattributes`) влияют на то, что
  писать в индекс — решено так:
  - текст разбивается на строки как в Monaco (последняя пустая строка = перевод строки в конце), у каждой строки свой EOL;
  - stage: `hash-object --path` прогоняет текст через clean-фильтры (autocrlf, eol, ident), как `git add`;
    unstage: `--no-filters` (HEAD и индекс уже «чистые»);
  - discard: строки из индекса получают EOL рабочей копии, если он отличается (CRLF-checkout при autocrlf);
  - `filter=` (LFS и др.) — частичные операции запрещены.
- 2026-10-22: GitKraken строит патч из модели Monaco (jsdiff) и применяет; выбран подход VS Code (новый текст +
  `hash-object`/`update-index`) — меньше зависит от формата патча и концов строк.
- 2026-10-22: `TextDecoder` по умолчанию съедает BOM и молча заменяет невалидный UTF-8 — при записи обратно это
  портило бы файлы. Теперь `ignoreBOM: true`, а не-UTF-8 версии помечаются `lossy` и не редактируются по строкам.
- 2026-10-22: «что видно, то и индексируется» — окно присылает line changes Monaco и выбранные строки, main сверяет
  SHA-256 обеих версий и совпадение строк вне изменений; при «Ignore whitespace» строки не индексируются.
- 2026-10-22: семантика выделения в Split: слева — удаления, справа — добавления; невыбранное удаление остаётся.
- 2026-10-22: операции над индексом выполняются по очереди (одна за другой) — нет гонок за `index.lock`.
- Для e2e: у каждого прогона свой профиль Electron (`XDG_CONFIG_HOME`) — иначе блокировка единственного
  экземпляра закрывает тестовый запуск, если владелец держит открытым `npm run dev`; HOME тестов — вне репозитория.
- 2026-10-26: по итогам замеров (`docs/research/competitors-2026-10.md`): (1) libgit2 не учитывает
  skip-worktree — в sparse checkout все файлы вне выборки показывались удалёнными (на linux — 97 217 «удалений» и
  5,5 ГБ в окне). Теперь у записей индекса с skip-worktree (индекс версии 3+) снимаются изменения рабочего дерева,
  как в `git status` (тесты: sparse checkout и ручной `update-index --skip-worktree`; при включённом sparse git сам
  снимает флаг с файлов, что лежат на диске, — это не меняли). (2) Списки изменений длиннее 300 записей рисуют
  только видимые строки (строка фиксированной высоты 24 px, распорки сверху и снизу). (3) Stage/unstage/discard
  передают пути git через stdin (`--pathspec-from-file=- --pathspec-file-nul`): нет предела длины командной строки
  (на Windows — ~32 тыс. символов), до 1 млн путей за запрос. Сквозная проверка: 2000 файлов — в DOM ~50 строк,
  прокрутка до конца, «Stage all» за раз.

## Итог (2026-10-22)

Реализовано: stage/unstage/discard файлов, hunk'ов (иконка в «желобе» Monaco, контекстное меню) и
выделенных строк (слева — удаления, справа — добавления); подтверждение Discard; коммит с хуками, Amend.
Подход VS Code: новый текст строится из изменений Monaco (`src/main/git/partial.ts`) и пишется
`git hash-object --path` + `git update-index --cacheinfo` (фильтры autocrlf/eol как у `git add`).
Отказ частичных операций: LFS/filter, бинарные, не-UTF-8, symlink/submodule, удалённые файлы,
устаревший вид (сверка SHA-256), включённый «Ignore whitespace». BOM сохраняется; Discard в CRLF-checkout — CRLF.
Тесты: partial (9, вкл. 500 случайных случаев), staging (15) — всего 112; e2e UI 17/17.
Не сделано: отдельный Hunk View (используется «Collapse unchanged» Monaco), ручная проверка владельцем.
