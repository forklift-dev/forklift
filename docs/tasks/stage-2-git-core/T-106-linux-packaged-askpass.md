# T-106. Исправить HTTPS askpass в упакованной Linux-сборке

## Цель

Восстановить вход по логину и паролю/токену для HTTPS-репозиториев в готовой Linux-сборке: Git должен запрашивать
учётные данные через окно Forklift, а не завершаться ошибкой наподобие `terminal prompts disabled`.

## Контекст

- T-024 реализовала askpass-мост: `src/main/askpass/server.ts` создаёт `forklift-askpass.sh`, передаёт его через
  `GIT_ASKPASS`/`SSH_ASKPASS` и запускает тот же executable с `--forklift-askpass`.
- `src/main/git/cli.ts` намеренно задаёт `GIT_TERMINAL_PROMPT=0`: сетевые операции не должны зависать в невидимом
  терминале, поэтому сломанный askpass оставляет Git без способа запросить логин и пароль.
- Существующие тесты проверяют askpass преимущественно в dev/test-окружении. На чистой Linux-системе в готовой
  сборке диалог не появляется, askpass не срабатывает, а Git сообщает, что terminal prompts отключены.
- Проверять нужно HTTPS remote с Basic-аутентификацией или токеном в поле пароля; пароль аккаунта на хостингах,
  которые его не принимают (например, GitHub), не является подходящим тестом.

## Этапы

- [x] Воспроизвести ошибку в опубликованном Linux-артефакте на чистой системе без настроенного credential helper;
  сохранить точный stderr Git и диагностировать запуск сгенерированного `forklift-askpass.sh`.
- [x] Исправить команду, окружение, права или жизненный цикл askpass так, чтобы helper надёжно запускался из
  упакованного приложения, в том числе если путь к приложению или профилю содержит пробелы.
- [x] Если helper не удалось запустить, показывать пользователю понятную причину вместо одной лишь ошибки
  `terminal prompts disabled`, не раскрывая секреты в UI или журнале.
- [x] Добавить сквозной тест готового Linux-артефакта с локальным HTTPS/HTTP Git-сервером и Basic-аутентификацией:
  запрос логина, маскированный запрос пароля/токена, успешный fetch/push и отмена.
- [x] Проверить сценарии с системным credential helper, без него и с сохранением через safeStorage; не менять
  пользовательский global Git config.

## Критерии готовности

- На чистой Linux-системе fetch/pull/push по HTTPS из упакованного Forklift открывает диалог логина и пароля/токена
  и успешно завершает операцию после корректного ответа.
- Отмена диалога завершает операцию без зависшего процесса; неверные данные можно ввести повторно.
- Логин допустимо показывать, но пароль/токен не попадает в Redux-состояние, аргументы процессов, operation log,
  stdout/stderr теста или файлы вне защищённого хранилища.
- Packaged E2E воспроизводит прежний дефект без унаследованного credential helper и проходит после исправления.
- Существующие проверки askpass, SSH и сетевых операций, `npm run typecheck`, `npm run lint` и `npm test` зелёные.

## Нюансы

- 2026-11-09: дефект обнаружен владельцем на чистой Linux-системе; видимая ошибка содержала
  `terminal prompts disabled`, а настроенный приложением askpass не показал диалог.
- Не исправлять проблему включением интерактивного терминального prompt: у GUI-процесса нет подходящего TTY, и
  операция может зависнуть. `GIT_TERMINAL_PROMPT=0` должен остаться защитой после починки askpass.
- Не ослаблять Electron fuse `runAsNode: false` и остальные настройки безопасности ради запуска helper.
- 2026-11-09: корневая уязвимость packaged-сценария — wrapper запускал `process.execPath` внутри AppImage mount,
  тогда как окружение Git намеренно очищено от `APPDIR` и AppImage-путей. Такой запуск обходит `AppRun` и может
  потерять поставляемые приложением библиотеки. Теперь проверенный `APPIMAGE` повторно запускается с
  `--forklift-askpass`; `AppRun` каждый раз восстанавливает полное окружение. Поддельный `APPIMAGE` не принимается,
  если executable не находится внутри соответствующего `APPDIR`.
- 2026-11-09: `remote` E2E теперь явно отключает system/global Git config. Новый static-runtime AppImage прошёл
  packaged E2E: запрос логина, маскированный пароль, неверный пароль, отмена, pull, push и force-push offer;
  секрет не попал в журнал HTTP-запросов. Electron fuses остались включены по прежней политике.
