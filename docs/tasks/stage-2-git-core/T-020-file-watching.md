# T-020. Слежение за файлами и автообновление

## Цель

Состояние репозитория обновляется само, когда пользователь меняет файлы или запускает git в терминале.

## Контекст

`nsfw` (GitKraken, MIT, N-API) уже в зависимостях и собирается под Electron (T-002).

## Этапы

- [ ] Watcher рабочего дерева и `.git` (refs, HEAD, index) через `nsfw` в main
- [ ] Debounce (≈300 мс) и объединение событий; игнорировать `.git/objects`, `node_modules` и пути из `.gitignore`
- [ ] Обновление через `loadRepo`; не запускать параллельно второе чтение — помечать «нужно ещё раз»
- [ ] Обновление при фокусе окна (как запасной механизм)
- [ ] Остановка watcher при закрытии репозитория

## Критерии готовности

- Изменение файла в редакторе или `git commit` в терминале отражается в UI за ≤1 с без ручного Refresh.

## Нюансы

- Большие репозитории: лимит inotify на Linux (`fs.inotify.max_user_watches`) — показывать понятное
  предупреждение, а не падать.
- Сейчас `loadRepo` читает всё (1000 коммитов + статус); для частых обновлений может понадобиться
  раздельное обновление статуса и истории.
