# T-107. Push новой ветки с созданием upstream из интерфейса

## Цель

Дать возможность одной операцией из интерфейса запушить текущую локальную ветку, которой ещё нет ни в одном
remote и для которой не настроен upstream, а затем привязать созданную удалённую ветку как upstream.

## Контекст

- Backend уже поддерживает этот сценарий в `src/main/git/remote.ts`: при явно выбранном remote выполняется
  `git push --set-upstream <remote> refs/heads/<branch>:refs/heads/<branch>`.
- `src/renderer/src/components/useRemoteActions.tsx` должен открыть выбор remote после ошибки об отсутствующем
  upstream, но определяет её по английскому тексту `/has no upstream branch/`.
- Ошибка создаётся через локализованный `t(...)`; при русском интерфейсе текстовый шаблон не совпадает, и
  пользователь видит ошибку вместо диалога Push. Разбор локализованного текста также хрупок при изменении Git.
- `UpstreamPicker` из T-095 показывает только уже существующие remote-tracking branches и потому сам по себе не
  решает сценарий первой публикации ветки.

## Этапы

- [x] Убрать распознавание отсутствующего upstream по английскому тексту ошибки; использовать состояние ветки
  либо структурированный код/тип результата, не зависящий от языка интерфейса и версии Git.
- [x] При Push ветки без upstream открыть подтверждение для единственного remote или форму выбора при нескольких;
  явно сообщить, какая удалённая ветка будет создана и станет upstream.
- [x] Выполнить push с `--set-upstream`, обновить состояние репозитория и сразу показать новую связь и счётчики в UI.
- [x] Корректно показать отказ сервера, ошибку авторизации, конфликт имён и отмену, оставив локальную ветку без
  ложной связи upstream при неуспешном push.
- [x] Добавить E2E на русском интерфейсе для одного и нескольких remote и для ветки, отсутствующей на сервере.

## Критерии готовности

- Для локальной ветки `feature`, которой нет на сервере и у которой нет upstream, кнопка Push позволяет выбрать
  `origin`, создаёт `origin/feature` и устанавливает `feature@{upstream}` в `origin/feature`.
- Сценарий работает при любой поддерживаемой локали и не распознаёт ветвление UI по тексту исключения.
- При одном remote требуется только понятное подтверждение; при нескольких можно выбрать нужный remote.
- После успешного push шапка и селектор upstream показывают новую связь без перезапуска приложения.
- E2E сначала подтверждает отсутствие remote branch, затем проверяет её создание и вывод
  `git rev-parse --abbrev-ref feature@{upstream}`; `npm run typecheck`, `npm run lint` и `npm test` зелёные.

## Нюансы

- 2026-11-09: дефект обнаружен владельцем на репозитории с новой локальной веткой без upstream и без одноимённой
  ветки в remote: из интерфейса не было возможности впервые опубликовать её и настроить tracking.
- Не предлагать сначала вручную создавать ветку на хостинге: обычный `git push -u` атомарно решает этот сценарий.
- Не путать первую публикацию с выбором уже существующей удалённой ветки в `UpstreamPicker`: это два разных
  действия, хотя после успешного push результат должен быть виден в одном и том же месте.
- 2026-11-09: renderer теперь до вызова IPC проверяет реплицированное `data.branch.upstream`; отсутствие upstream —
  нормальное состояние, а не распознаваемая по тексту ошибка. Английский regex удалён.
- 2026-11-09: оставшееся ветвление при отклонённом push также переведено с префикса `Rejected:` на стабильный
  IPC-код `push-rejected`; локализованный текст используется только для показа пользователю.
- 2026-11-09: новый E2E `push-upstream` в русской локали проверяет подтверждение при одном remote, выбор `backup`
  при двух remote, создание отсутствующих `main`/`feature`, запись tracking и отсутствие `feature` в неверном
  remote. Тест прошёл в dev-сборке и в новом static-runtime AppImage.
