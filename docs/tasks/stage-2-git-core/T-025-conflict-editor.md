# T-025. Встроенное разрешение конфликтов

## Цель

Трёхпанельный редактор конфликтов (ours / theirs / результат) для merge, rebase, cherry-pick и
возврата stash; выбор блоков целиком или правка результата вручную; отметка «разрешено».

## Этапы

- [x] Версии конфликта из индекса (стадии 1/2/3) через nodegit
- [x] Редактор: блоки конфликтов, «взять ours/theirs/оба», ручная правка результата (Monaco)
- [x] Сохранить результат и проиндексировать; продолжить/прервать merge/rebase (и cherry-pick/revert; skip)
- [x] Внешний merge tool (T-014) — кнопка-альтернатива
- [x] Баннер операции: что идёт (merge/rebase с прогрессом/cherry-pick/revert), сколько конфликтов, Continue/Skip/Abort
- [x] Целиком «наша/их» версия файла, в том числе удаление (modify/delete)

## Нюансы

- В GitKraken в worker'е есть разбор конфликтов (`conflictIndexMap`) — посмотреть при реализации.
- 2026-10-23: GitKraken строит свой diff3 из трёх версий и собирает результат галочками по строкам. Мы берём
  **файл с маркерами git** как результат (как VS Code): конфликты совпадают с тем, что показал бы git
  (его алгоритм слияния, `merge.conflictStyle` diff3/zdiff3 поддерживается — блок base подсвечивается), а ours/theirs
  из стадий индекса показываются сверху для справки. Разбор маркеров — `src/shared/conflicts.ts`, с тестами.
- 2026-10-23: биндинг nodegit `Index.getByPath(path, stage)` игнорирует стадию — для стадий 1–3 используется
  `conflictGet` (возвращает `ancestor_out/our_out/their_out`).
- 2026-10-23: сохранение защищено хэшем: если файл изменился на диске с момента открытия (редактор, merge tool,
  `git checkout --merge`), запись отклоняется. «Save and mark resolved» с оставшимися маркерами — только после
  подтверждения. Ctrl+S — сохранить; закрытие с несохранёнными правками — подтверждение.
- 2026-10-23: продолжение merge = `git commit --no-edit` (сообщение из MERGE_MSG; хуки работают), остальные —
  `--continue`; при `GIT_EDITOR=:` git оставляет подготовленное сообщение. Ошибка продолжения показывает вывод git/хука.
- 2026-10-23: «ours/theirs» во время rebase — как у git: ours = ветка, на которую перебазируем, theirs —
  применяемый коммит; подписи панелей берутся из маркеров (`HEAD` / `<sha> (сообщение)`), чтобы не путать.
- 2026-10-23: бинарные, слишком большие и не-UTF-8 файлы не редактируются — только «Use our/their file» и внешний
  инструмент.
- 2026-10-23: попутно исправлено: панель кнопок diff не переносилась на узком центре (после появления левой панели
  кнопки уезжали под правую панель) — теперь переносится.
- 2026-10-23: проверено: юнит-тесты (маркеры; ConflictService на реальном git: стадии, сохранение, stale-хэш,
  modify/delete, continue/abort merge, skip/abort rebase с прогрессом) и сквозной набор `conflicts` (15 проверок).
