# T-026. Слежение за файлами и автообновление

## Цель

Состояние репозитория обновляется само при изменении файлов и при работе git из терминала.

## Этапы

- [x] Watcher рабочего дерева и `.git` (HEAD, refs, index) через `nsfw` (GitKraken, MIT)
- [x] Debounce ≈300 мс, объединение событий; игнор `.git/objects` и путей из `.gitignore`
- [x] Без параллельных чтений: флаг «нужно ещё раз»; раздельное обновление статуса и истории
- [x] Обновление при фокусе окна как запасной механизм; остановка при закрытии репозитория
- [x] Предупреждение о лимите inotify на Linux

## Нюансы

- 2026-10-23: следим только за **активной** вкладкой (inotify-наблюдатели на каждую папку дерева — на много
  вкладок их не напасёшься). При переключении вкладки прежний наблюдатель останавливается, новая вкладка
  перечитывается — изменения, сделанные пока она была в фоне, видны сразу.
- 2026-10-23: что считается изменением: в git-каталоге — HEAD, index, refs/**, packed-refs, config, состояния
  merge/rebase/cherry-pick/revert, `*.lock` и `objects/`, `logs/`, FETCH_HEAD — нет (objects исключены и в самом nsfw).
  В рабочем дереве путь проверяется по `.gitignore` (`Ignore.pathIsIgnored`); больше 200 путей за раз — без проверки.
- 2026-10-23: «тихое» обновление (`refreshRepo`): без `loading` (нет спиннеров и мигания), ошибка не показывается —
  остаются прежние данные (git в терминале может держать index.lock), следующее событие повторит. Обычная загрузка
  (`loadRepo`) имеет приоритет: результат тихого обновления во время неё отбрасывается.
- 2026-10-23: «раздельное обновление статуса и истории»: история не реплицируется (T-022) — тихое обновление
  перечитывает статус, ветки и `historyVersion`; страницы истории перечитываются окном только при новой версии.
  Открытый diff рабочей копии перечитывается (зависит от `loadedAt`).
- 2026-10-23: linked worktree: следим за деревом и за его git-каталогом (`.git/worktrees/<name>`), но не за общим
  `refs/` основного репозитория — коммит в другой worktree появится по фокусу окна. Доделать с T-044.
- 2026-10-23: лимит inotify (ENOSPC) → уведомление с командой для `sysctl`; дальше обновление по фокусу окна.
- 2026-10-23: проверено: юнит-тесты (классификация путей, Refresher, RepoWatcher на временном репозитории с реальным
  nsfw, WatchManager) и сквозной набор `watch` (10 проверок).
