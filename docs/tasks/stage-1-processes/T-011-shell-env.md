# T-011. Окружение login-shell (PATH на macOS/Linux)

## Цель

Внешние программы, запущенные приложением, видят то же окружение, что и в терминале пользователя
(`PATH` с Homebrew, nvm, `~/.local/bin`, переменные из `.zshrc`/`.bashrc`).

## Контекст

GUI-приложения, запущенные из Dock (macOS) или меню (часть Linux-окружений), получают урезанное
окружение. Без этого `code`, `git` из Homebrew, `meld` и т.п. «не находятся».

## Этапы

- [x] `src/main/process/shellEnv.ts`: один раз при старте `$SHELL -i -l -c "printf MARK; /usr/bin/env -0; printf MARK"` через ProcessRunner
- [x] Случайные маркеры + `env -0`, разбор по `\0`; таймаут 10 с; при ошибке — `process.env` и сообщение в лог
- [x] Не запускать при старте из терминала (`process.stdout.isTTY`) и на Windows; `FORKLIFT_SHELL_ENV=force|off` переопределяет
- [x] zsh, bash, dash/sh — проверены на реальных shell'ах; fish — тест есть, пропущен (fish не установлен); csh/tcsh — `-ic`; nu/xonsh/pwsh — не поддерживаются (используется окружение приложения)
- [x] Результат — базовое env ProcessRunner (`setBaseEnv(promise)`): команды ждут резолва; сам shell запускается с `replaceEnv`, чтобы не ждать себя
- [x] Тесты: разбор вывода, выбор аргументов, эвристика запуска; интеграция с bash/zsh/dash во временном HOME; зависший rc-файл; отсутствующий shell
- [x] Живая проверка (запуск «как из меню»: без TTY, урезанный PATH, временный HOME с `.zshrc`): 5/5
- [ ] Ручная проверка на macOS с запуском из Dock (нет macOS-машины — T-003 или владелец)

## Критерии готовности

- На macOS при запуске из Dock `which code`/`which git` внутри приложения совпадает с терминалом.
- Старт приложения не задерживается: env резолвится асинхронно, первые git-операции идут через nodegit.

## Нюансы

- `.zshrc` может печатать в stdout (приветствия, `nvm`) — поэтому маркеры обязательны.
- 2026-10-22: в rc-файлах видна `FORKLIFT_RESOLVING_ENVIRONMENT=1` — можно пропускать тяжёлую интерактивную
  настройку (по аналогии с `VSCODE_RESOLVING_ENVIRONMENT`). Из результата она удаляется вместе с `_`, `SHLVL`, `PWD`, `OLDPWD`.
- 2026-10-22: с реальным `.zshrc` владельца (zsh 5.9) резолв ≈ 1 с. Окно это не задерживает: ждут только
  первые запуски процессов через ProcessRunner; чтение репозитория идёт через nodegit без процессов.
- 2026-10-22: результат без `PATH` считается неудачей — иначе сломается поиск любых программ.
- Fuse `RunAsNode` выключен, поэтому печатать окружение через `process.execPath -p` (как VS Code) нельзя —
  используем системный `/usr/bin/env -0` (есть на Linux и macOS).
- Интерактивный shell может зависнуть на запросе (например, `oh-my-zsh` update) — таймаут обязателен,
  stdin — пустой.
