# T-011. Окружение login-shell (PATH на macOS/Linux)

## Цель

Внешние программы, запущенные приложением, видят то же окружение, что и в терминале пользователя
(`PATH` с Homebrew, nvm, `~/.local/bin`, переменные из `.zshrc`/`.bashrc`).

## Контекст

GUI-приложения, запущенные из Dock (macOS) или меню (часть Linux-окружений), получают урезанное
окружение. Без этого `code`, `git` из Homebrew, `meld` и т.п. «не находятся».

## Этапы

- [ ] `src/main/process/shellEnv.ts`: один раз при старте выполнить `$SHELL -ilc '<печать env между маркерами>'` через ProcessRunner
- [ ] Маркеры + `env -0` (или аналог), разбор по `\0`; таймаут 10 с, при ошибке — `process.env` и предупреждение в лог
- [ ] Не запускать, если приложение стартовало из терминала (окружение уже полное) и на Windows
- [ ] Поддержать shell'ы: zsh, bash, fish (у fish свой синтаксис `-ilc` — проверить)
- [ ] Результат — базовое env для `run`/`launch` (до санитизации из T-010)
- [ ] Тест разбора вывода (маркеры, мусор от `.zshrc` до и после маркеров)

## Критерии готовности

- На macOS при запуске из Dock `which code`/`which git` внутри приложения совпадает с терминалом.
- Старт приложения не задерживается: env резолвится асинхронно, первые git-операции идут через nodegit.

## Нюансы

- `.zshrc` может печатать в stdout (приветствия, `nvm`) — поэтому маркеры обязательны.
- Интерактивный shell может зависнуть на запросе (например, `oh-my-zsh` update) — таймаут обязателен,
  stdin — пустой.
