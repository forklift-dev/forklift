# T-076c. Отдельное окно Forklift для git mergetool

## Цель

Разрешать git-конфликт в отдельном окне Forklift, используя BASE, LOCAL, REMOTE и MERGED, полученные от Git.

## Контекст

Редактор конфликтов T-025/T-072 работает с индексом репозитория; внешний `git mergetool` передаёт временные файлы и ждёт завершения. Внешнее окно не должно запускать операции git поверх основного редактора конфликта.

## Этапы

- [x] Показать BASE/LOCAL/REMOTE и редактируемый результат MERGED в отдельном окне.
- [x] Сохранять только в переданный MERGED путь; не менять другие файлы и не записывать файлы при отмене.
- [x] Поддержать именованные аргументы и позиционные формы KDiff3/Meld; сообщать Git об отмене/ошибке ненулевым кодом.
- [x] Проверить конфликтный и бесконфликтный вызовы `git mergetool`, отмену, пробелы в путях и запуск рядом с основным окном.

## Критерии готовности

- Git получает разрешённый файл только после явного сохранения результата; успешный выход принимается согласно `trustExitCode`.
- BASE/LOCAL/REMOTE соответствуют сторонам Git; отмена не записывает результат и сообщает неуспех.

## Нюансы

- 2026-10-27: не использовать служебный `*.orig` файл Git; его создание контролируется пользовательской настройкой `mergetool.keepBackup`.
- 2026-10-27: BASE/LOCAL/REMOTE загружаются через одноразовый IPC; путь MERGED остаётся в main process. Перед сохранением сверяется исходная версия MERGED, лимит результата — 10 MiB; только явное «Save and close» записывает результат и возвращает Git код 0, закрытие окна возвращает 1.
- 2026-10-27: распознаны positional формы из системных Git-скриптов KDiff3 (`-o MERGED BASE LOCAL REMOTE`, с вариантом без BASE) и Meld (`--output=MERGED LOCAL BASE REMOTE`, legacy `LOCAL MERGED REMOTE`). Проверки: typecheck, lint, 11 parser tests, e2e git-mergetool и git-difftool.
