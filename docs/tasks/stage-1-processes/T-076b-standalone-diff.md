# T-076b. Отдельное окно Forklift для git difftool

## Цель

Показывать две версии файла в отдельном окне Forklift, когда Git запускает приложение как внешний diff tool.

## Контекст

Существующий `DiffView` принимает git-backed `DiffTarget`; внешний режим получает уже подготовленные Git файлы `$LOCAL` и `$REMOTE`. Обычный UI не должен открывать вкладку репозитория или менять её выбор.

## Этапы

- [x] Открыть изолированное окно для аргументов из T-076a и закрывать процесс только после закрытия окна.
- [x] Безопасно загрузить две версии, отобразить встроенный diff в Monaco, корректно показать бинарные, отсутствующие и слишком большие файлы.
- [x] Поддержать Escape/закрытие окна и вернуть Git код выхода 0 после закрытия окна; ошибки запуска завершаются ненулевым кодом.
- [x] Проверить запуск при уже открытом Forklift и отдельно от основного окна.

## Критерии готовности

- Временный репозиторий запускает `git difftool` с Forklift; сравниваются те же версии, что передал Git.
- Git ждёт закрытия окна и получает согласованный код выхода; обычные окна и состояние приложения не меняются.

## Нюансы

- 2026-10-27: UI должен читать только переданные Git пути, с валидацией и без разрешения произвольной навигации через IPC.
- 2026-10-27: Git передаёт `$LOCAL` как временный абсолютный файл, а `$REMOTE` и `$MERGED` может передать относительно cwd репозитория; CLI разрешает относительные пути от cwd.
- 2026-10-27: отдельное окно использует отдельный процесс без single-instance lock, одноразовый IPC и `app://` renderer; e2e подтвердил вызов через `git difftool`, точные стороны сравнения, ожидание закрытия Git и соседство с открытым основным окном.
