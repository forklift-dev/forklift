# T-086. Каталоги переводов и автоматическая проверка

## Цель

Сделать строки интерфейса доступными для перевода без правки TypeScript и подготовить формат, пригодный для pull request и будущей платформы переводов.

## Контекст

Сейчас английский текст служит ключом `t()`, а русский перевод хранится по частям приложения в `src/shared/i18n/strings/*.ts`. Есть контекстные префиксы, параметры и формы множественного числа; правила описаны в [docs/i18n.md](../../i18n.md). Переводчики должны получать исходный текст и контекст, не теряя этих свойств.

## Этапы

- [ ] Выбрать открытый текстовый формат каталогов по локалям с поддержкой контекста, параметров и plural-форм; зафиксировать схему и правила сортировки.
- [ ] Вынести английский источник и русский перевод в каталоги, сохранив нынешнее поведение `t()`, `tx()` и `translate()`.
- [ ] Обеспечить проверку соответствия каталогов вызовам в коде и текстам схем настроек/команд, включая удалённые и новые строки.
- [ ] Проверять дубли, синтаксис, одинаковый набор параметров и необходимые формы множественного числа в CI.

## Критерии готовности

- Перевод существующей строки меняется в каталоге без изменения TypeScript; английский и русский интерфейсы работают как до миграции.
- Новая строка и ошибка параметров дают понятное сообщение проверки; каталоги обновляются воспроизводимо.
- `npm run typecheck`, `npm run lint`, `npm test` и `npm run test:e2e` проходят.

## Нюансы

- 2026-10-27: не заменять сообщения Git и вывод внешних программ переводами; их формат нужен парсеру.
