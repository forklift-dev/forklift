# T-075. Хранение профилей и настроек на сервере

## Цель

Пожелание владельца (2026-10-26, «надо подумать»): профили (имя, email, ключи подписи) и, возможно, настройки — не только локально, а с синхронизацией между машинами.

## Контекст

- Профили и ключи — T-053 (`profiles.list` в settings.json, SSH/GPG-ключи в ~/.ssh и gpg); учётные записи хостингов и токены — T-065 (токены только в safeStorage).
- В «Сознательно не делаем» (README) — облачные функции GitKraken, требующие их сервера.

## Этапы

- [ ] Решить с владельцем, где хранить (варианты ниже) и что синхронизировать
- [ ] Шифрование на клиенте (ключ/пароль пользователя), секреты никогда не уходят открытыми
- [ ] Слияние изменений с разных машин, конфликты
- [ ] Экспорт/импорт файлом как минимальный вариант без сервера

## Критерии готовности

- Профили переносятся на другую машину без ручного копирования; секреты не покидают машину незашифрованными
- Юнит/интеграционные тесты, `npm run typecheck`, `lint`, `test`, сквозной набор в `npm run test:e2e` — зелёные

## Нюансы

- 2026-10-26: **вопросы владельцу**: (1) где хранить — приватный репозиторий на GitVerse/Forgejo/GitHub (через уже добавленную учётную запись), свой сервер, или пока только экспорт/импорт файлом? (2) что синхронизировать — только профили (имя, email, выбор ключа) или все настройки, темы и сочетания клавиш? (3) приватные ключи — никогда (только публичные и ссылки на них), или зашифрованными паролем?
