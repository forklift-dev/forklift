# T-053. Профили, SSH- и GPG-ключи

## Цель

Несколько профилей (имя/email для коммитов, SSH-ключ, настройки) с быстрым переключением; генерация и выбор SSH-ключей; подпись коммитов GPG/SSH.

## Контекст

- В GitKraken: Profile 57, SSH/GPG 191 строка (по `strings.json`); их реализация — ориентир по поведению, код свой.

## Этапы

- [x] Профили: user.name/email на уровне репозитория или глобально по выбору
- [x] SSH: использование ssh-agent, выбор ключа (core.sshCommand), генерация ed25519 (`ssh-keygen`)
- [x] Подпись: commit.gpgsign, gpg.format=ssh/openpgp, выбор ключа; проверка подписи в деталях коммита
- [x] Тесты

## Критерии готовности

- Коммиты подписываются и проверяются; профили переключаются
- Юнит/интеграционные тесты, `npm run typecheck`, `lint`, `test`, сквозной набор в `npm run test:e2e` — зелёные

## Нюансы

- 2026-10-23: профиль = подпись в списке + user.name/email + SSH-ключ для remote + подпись коммитов (нет / SSH /
  GPG с выбором ключа). Хранятся в настройке `profiles.list` (settings.json; парольных фраз и ключей там нет —
  только пути и id). «Use for all repositories» пишет в `git config --global`, «Use for this repository» — в
  `--local`; то же — палитрой «Switch profile…» (Enter — глобально, Shift+Enter — только этот репозиторий).
  Текущий профиль определяется по совпадению имени и email в действующем git config; форма коммита показывает
  «as Имя <email> · Профиль · signed».
- 2026-10-23: **вопрос владельцу:** в GitKraken профиль — это ещё и отдельный набор настроек приложения/вкладок/
  интеграций. Здесь профиль переключает только личность git и ключи; общие настройки одни на всех. Если нужны
  «полные» профили (свои Preferences, вкладки) — это отдельная задача: меняет хранение settings/session.
- 2026-10-23: SSH-ключ профиля — `core.sshCommand = ssh -i '<ключ>' -o IdentitiesOnly=yes`; без ключа профиль
  убирает только такой (свой) `core.sshCommand`, чужой не трогает. Ключи из `~/.ssh` (пары `*.pub` + приватный),
  отпечаток и тип — `ssh-keygen -l`; ssh-agent — `ssh-add -l` (если `SSH_AUTH_SOCK`), «Add to agent» —
  `ssh-add` с запросом парольной фразы через askpass-мост приложения.
- 2026-10-23: генерация — `ssh-keygen -t ed25519` в `~/.ssh` (папка 0700). Парольная фраза передаётся ssh-keygen
  аргументом `-N` (иначе он читает её только с терминала) — на время работы ssh-keygen она видна другим процессам
  этого пользователя в списке процессов; нигде не сохраняется. Можно без фразы.
- 2026-10-23: подпись — `gpg.format` (`ssh`/`openpgp`), `user.signingkey` (для SSH — путь к .pub, для GPG —
  отпечаток), `commit.gpgsign`/`tag.gpgsign`; «не подписывать» в репозитории пишет `commit.gpgsign=false`, чтобы
  перекрыть глобальное. GPG-ключи — `gpg --list-secret-keys --with-colons`. Ключ GPG с парольной фразой
  спрашивает свой pinentry (графический); SSH-ключ с фразой для подписи нужно добавить в ssh-agent.
- 2026-10-23: проверка подписи в деталях коммита — `git show -s --format=%G?…` в фоне: Verified / Valid, key not
  trusted / expired / Bad / Cannot be checked, формат и подписавший. Для SSH-подписей приложение ведёт свой файл
  allowed signers (`userData/allowed_signers`, из SSH-ключей профилей) и передаёт его через `-c`, только если у
  пользователя не задан свой `gpg.ssh.allowedSignersFile`.
- 2026-10-23: проверено: юнит-тесты (`profiles/service.test.ts` — применение глобально/в репозиторий, ssh-команда,
  генерация и список ключей, подпись и проверка SSH и OpenPGP во временных HOME/GNUPGHOME) и сквозной набор
  `profiles` (15 проверок: генерация ключа, профиль с SSH-подписью, подписанный коммит «Verified», переключение).
